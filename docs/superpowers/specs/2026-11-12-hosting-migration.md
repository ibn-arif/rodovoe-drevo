# Перенос на хостинг: PHP + MySQL вместо Supabase

Дата: 2026-11-12. Решение владельца: данные хранить в России, на его хостинге (ispmanager, PHP 8.4, MySQL/MariaDB);
сайт — на домене pamyat-roda.ru там же.

## Что не меняется

Страницы, черновик, роли и ссылки (owner/edit/view, токены в `#t=`, в базе только sha256-хэши), все правила правок,
конфликтов, истории и отката. Существующие ссылки продолжают работать: хэши переносятся как есть.

## Что меняется

- **API**: `api/index.php` — POST JSON `{"fn": "...", "args": [...]}` → `{"data": ...}` или HTTP 400 `{"error": "код"}`.
  Те же 8 функций и коды ошибок, что у Postgres-функций (`create_tree`, `open_tree`, `tree_version`, `save_changes`,
  `revert`, `get_history`, `deleted_items`, `ping`). Логика — в `api/lib.php` (PHP, PDO).
- **База**: MySQL/MariaDB (InnoDB, utf8mb4), схема `api/schema.mysql.sql`. В тестах — SQLite через тот же PDO.
  SQL пишется переносимым: без CTE и JSON-функций базы, обход ветки — в PHP, JSON хранится текстом,
  время — ISO-строкой из PHP. Блокировка древа: MySQL — `SELECT … FOR UPDATE`, SQLite — `BEGIN IMMEDIATE`.
- **Доступы к базе** — в `~/www/pamyat-roda.config.php` вне корня сайта (не в git, не доступен из браузера).
- **Адрес клиента** для лимитов — `REMOTE_ADDR` (проверить на сервере, нет ли прокси).
- **Клиент**: `js/api.js` зовёт `api/` через `fetch` вместо supabase-js; остальной фронтенд без изменений.
- **Тесты**: 44 теста базы переносятся на HTTP к `php -S` с SQLite (тот же смысл, те же сценарии);
  e2e-тесты — через тот же PHP-сервер вместо PGlite.
- **Выкладка**: `scripts/deploy.sh` — `lftp mirror -R` сайта и `api/` в `www/pamyat-roda.ru` (FTP с TLS).
- **Перенос данных**: выгрузка всех таблиц из Supabase → `private/` → импорт скриптом на сервере, сверка числа строк.
- **После переноса**: GitHub Pages оставить только для перенаправления старых ссылок github.io; Supabase и
  будильник отключить после недели без проблем.

## Не делаем

Не меняем модель данных и поведение сайта. Не добавляем регистрацию.
